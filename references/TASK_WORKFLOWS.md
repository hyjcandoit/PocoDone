# Task creation & breakdown workflows

## 1. 为什么只要一个创建入口

“原始任务表”“本周进度”“本月进度”“每日任务”只是**同一个 Notion 数据库**的不同视图。在其中任意位置新增一条记录，底层都只创建一条任务。推荐从原始任务表/样板视图添加，以方便设置完整属性。不要把任务复制到多张表形成重复记录。

## 2. 简单任务 — 一次交付

例：核对课程报名收据。

- 父任务记录：`任务类型=简单任务`、`分类=每周计划`、`状态=待开始`、`进度追踪=true`、日期、优先级、所属项目。
- 不新增每日子任务；必要时在每日视图中看不到它，因为每日视图只显示 `分类=每日计划 AND 所属进度 IS NOT EMPTY`。
- 简单任务的完成操作：直接将**本条父任务**状态设为 `已完成`。没有子任务时进度通常由 0% 变为 100%。
- 如果简单任务要“在每日执行中勾选”，有两种路线：把它设为一条每日计划（但需要确认是否仍要在周/月视图中跟踪），或将它改成有 1 条每日子任务的父任务（该步骤完成后 100%）。不要同时将两个动作当作两件独立成果。

## 3. 大型任务 — 有明确交付阶段

例：完成一份申请文书。

**父任务**：`分类=本月计划` 或 `每周计划`，`任务类型=大型任务`，有明确计划截止日，`进度追踪=true`，进度类别=文书。

**每日子任务**（仅作为示意，按事实改）：

| 子任务 | 状态 | 进度贡献 |
|---|---|---|
| 整理大纲 | 已完成 | 25% |
| 完成第一版 | 已完成 | 25% |
| 反馈后修订第二版 | 进行中 | 0%（此阶段还未完成） |
| 完成第三版 | 待开始 | 0% |

父任务进度为 50%。请勿把“第三版完成”理解为“提交申请已成功”。

## 4. 不同任务分类的拆分约定

| 类别 | 拆分建议 | 验收依据 |
|---|---|---|
| CS50P / 一周课程 | 课程学习 + PSet 测试/提交 | 课程可运行例题、作业提交结果 |
| 文书 | 大纲、第一版、第二版、第三版 | 可读、可审核的具体文本版本 |
| AI/MVP | 数据导入、统计、清洗、API 集成、测试、部署等按项目实际需求拆 | Notebook、运行日志、可用演示、测试记录 |
| 学校申请材料 | 官方要求核对、CV/LOR材料、个人素材、系统预审等 | 有记录的核对结果、材料列表 |
| SQL 学习 | 明确学习范围 + 完成一次可运行查询 | 实际 SQL 和结果/笔记 |

默认对子任务**等权**。如用户确实需要工时或难度加权，要另加权重字段和适当公式，不可默默修改已显示的进度定义。

## 5. 复制页样板 vs 原生 Notion 模板

可以在任务数据库创建两个样板页：

- `【模板样板】简单任务｜复制我并修改`
- `【模板样板】大型任务｜复制我并拆分步骤`

推荐样板属性：`进度追踪=false`、`本周重点=false`、无日期、状态=待开始、`任务类型` 分别预设简单/大型。用视图筛选标题中 `【模板样板】` 让它们集中显示。使用时**复制页面**并设为真实任务，取消样板标志；不要直接完成样板。

**限制：**这些是数据库记录样板（可 Duplicate），并非 Notion UI `新建 ▼` 下注册的 Database Templates。前者无须升级套餐；后者可以由用户在 Notion UI 中手动创建，也可能受到连接器接口支持情况限制。两者都不能无条件自动生成 AI 子任务。

## 6. 在本周和本月同时展示

每条**需要跟踪进度的真实父任务**：

- `进度追踪=true` → 当前实例的本月总进度可见（但此视图实际上不是严格自然月过滤）。
- `本周重点=true` 且 `进度追踪=true` → 本周进度可见。
- `展示序号` 是显示顺序，不是唯一 ID；新任务没有序号可能被排序到末尾。
- `逾期提示` 会在超过原截止日且未完成时自动显示文字；Status 的红色选项仍须手动或经授权的定时运行维护。

## 7. 迁移旧遗留任务

先从所有历史日期里查询未完成父任务，不依赖标题；给上月未完成的父任务设置进度追踪和本周重点。在它们**没有现有子任务**的情况下，可按真实剩余工作拆出每日步骤；如果已有子任务，不要再生成相同执行事项。

案例：旧父任务“整理项目材料库”（已过期、未完成）→ 两条子任务“核对截止日期与官方链接”“整理 CV/LOR 材料列表”。两个步骤均为“逾期待办”，关联旧父任务；父任务不会因为进入新月而改掉原始截止日。每完成一条，父任务的进度增长 50%。

若历史每日记录都已标记完成，不得因上层未完成就自行把历史记录改回未完成；应基于确有剩余的工作新建步骤并写明用途。

## 8. 最终验证

核对四件事：父任务中能看到 `每日步骤`；每条每日任务的 `所属进度` 指向正确的父任务；周/月只显示 `进度追踪=true` 的真实父任务；样板页不进入进度图表。
