# Database schema — v2.1

## 设计原则

单库、同表父子任务、双向 Relation。最小版本可只建立基础字段；希望自动计算子任务进度时应补齐 Relation/Formula/Rollup。不把“每日、每周、本月”建成三个彼此隔离的数据库。

| 字段（参考中文名） | Notion 类型 | 选项 / 用途 |
|---|---|---|
| 任务 | Title | 可验收的动作或成果 |
| 分类 | Select | 每日计划、每周计划、本月计划 |
| 任务类型 | Select | 简单任务（green）、大型任务（blue）；历史记录可为空 |
| AI 拆分状态 | Select | `待拆分` (yellow)、`已拆分` (green)、`需确认` (orange)、`无需拆分` (gray)；v2.1 新增，父任务的幂等状态标记 |
| 日期 | Date | 单日或日期区间；用于到期判断，区间的 `end` 视作截止日 |
| 优先级 | Select | P0 red、P1 orange、P2 blue、P3 gray |
| 状态 | Status | 待开始 gray、进行中 blue、逾期待办 red、已完成 green |
| 所属项目 | Select | 自行定义，别硬编码学校、团队和个人名字 |
| 进度类别 | Select | CS50P、文书、AI项目、其他；可替换为用户实际类别 |
| 执行说明 | Rich text | 验收条件、交付物、约束、顺延背景 |
| 进度追踪 | Checkbox | 真实父任务显示在进度视图时为 true；模板样板 false |
| 本周重点 | Checkbox | 用于周视图筛选；由人工或独立定时任务维护 |
| 展示序号 | Number | 进度视图排序；不显示也可以参与排序 |
| 所属进度 | Relation → 同一数据源 | 每日子任务指向父任务 |
| 每日步骤 | 反向 Relation → 同一数据源 | 父任务的子任务集合，与所属进度双向配对 |
| 步骤完成 | Formula(Boolean) | `prop("状态") == "已完成"` |
| 步骤完成率 | Rollup(number) | relation=每日步骤；target=步骤完成；aggregation=percent_checked |
| 进度百分比 | Formula(Number) | 子任务占比优先；无子任务使用兼容 fallback 或 Status |
| 进度条 | Formula(String) | `█`/`░` 十格文字条 |
| 自动逾期 | Formula(Boolean) | 自动判断是否超过截止日（不直接改 Status） |
| 逾期提示 | Formula(String) | 根据自动逾期展示红色文字提醒 |
| 本周自动范围 | Formula(Boolean), optional | 是否与当前自然周交集；**未必能被连接器保存为视图筛选** |
| 动态周待办 | Formula(Boolean), optional | 本周自动范围 OR 自动逾期，仅作为辅助字段 |

## 旧版兼容字段

生产部署可能保留以下 Checkbox：`课程学习完成`、`PSet提交完成`、`大纲完成`、`第一版完成`、`第二版完成`、`第三版完成`。它们只在**没有子任务**时参与旧流程的回退进度计算。迁移时不要一次性删除旧字段。

## 完成规则

- **唯一完成依据**：`状态` 恰好是 `已完成`。
- `AI 拆分状态` **不是任务完成状态**，仅用于控制子任务生成流程。`已拆分` 不等于任务已经完成。
- 红色 `逾期待办` 在 Notion Status 的 *In Progress* 组，仅表示未完成且需要处理。不能把它算作完成。
- 父任务有子任务时，进度依子任务；但 Status 可能仍保留“进行中/逾期待办”，需在验收后更新。
- 不要同时把子任务与父任务都作为独立成果加入图表平均值。子任务建议 `进度追踪=false`。
- 当原来的“简单任务”被拆分成多个步骤，务必验证它的进度计算由 Status fallback 切换为 Rollup，导致进度可能重新计算（属预期变更，告知用户）。

## 示例结构

```text
父任务（分类=每周计划，任务类型=大型任务，进度追踪=true）
 ├─ 子任务 A（分类=每日计划，所属进度=父任务）
 ├─ 子任务 B（分类=每日计划，所属进度=父任务）
 └─ 子任务 C（分类=每日计划，所属进度=父任务）

父任务.每日步骤 反向自动列出 A/B/C
父任务.步骤完成率 = 完成子任务数 / 全部子任务数
```

## CSV 导入限制

CSV 只能创建普通文本/基本日期/选择类列。**不能用 CSV 自动创建双向 Relation、Rollup、Formula、视图、自动化或数据库模板**。先导入 [../notion_tasks_template.csv](../notion_tasks_template.csv)，再依照本文件在 Notion UI/授权连接器中配置。

## v2.1 自动拆分状态的设置

| `AI 拆分状态` | 行为 | 自动化是否处理 |
|---|---|---|
| 待拆分 | 新增的大型任务等待 AI 识别、拆解和关联 | 仅当 `任务类型=大型任务` 且不是样板或已完成任务 |
| 已拆分 | 子任务创建并核对成功 | 跳过；确保重复运行不重复拆分 |
| 需确认 | 必要字段缺失，或已有步骤与预期存在冲突 | 跳过，等待用户确认 |
| 无需拆分 | 简单任务、每日子任务等 | 跳过 |

适合新建样板预设：大型样板 `AI 拆分状态=待拆分`，简单样板 `AI 拆分状态=无需拆分`；**样板标题带 `【模板样板】` 时自动跳过**。克隆样板用于真实工作后才会被自动化检查。独立定时任务并非 `Select` 字段天然自带的功能。
