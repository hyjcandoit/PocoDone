# AI 自动拆分：每日 08:00 检查工作流（v2.1）

> 这是可复用的设计与 Agent 操作规范；不是 Notion 内置自动化，也不是 standalone 程序。**复制 Skill 不会安装定时任务。**

## 触发条件

- 用户主动配置或授权的外部定时任务每日按当地时区检查；示例排程 **08:00，周一至周日**。
- 数据源为同一个 Notion 任务库；无需新建一个“每日任务库”。
- 检索 `任务类型=大型任务` 且 `AI 拆分状态=待拆分` 的真实父任务。
- **必跳过**：标题含 `【模板样板】` 的样板、历史 `任务类型` 为空的行、`状态=已完成`、`AI 拆分状态` 不是“待拆分”的行。
- 子任务只引用该父任务的 `所属进度`；父任务则通过反向 `每日步骤` 获取子项。

## 处理流程（每次运行）

1. 读取数据库 schema、候选任务以及子任务现状，不依赖上次运行的缓存。
2. 对每条候选任务，检查 `每日步骤` 和反向 `所属进度` 是否已经关联子任务。**如果已有子项，不可以简单再拆一批**；核对其语义与原目标。符合时可标记 `已拆分`，出现差异则标 `需确认`。
3. 对没有子项的候选任务，读取真实目标、说明、日期区间、优先级、进度类别、所属项目。用户提供的阶段和验收标准高于通用模板。
4. 拆分规则：`CS50P` 课程 + PSet；文书大纲、V1、V2、V3；AI 项目按可验收里程碑；其他 2–6 个不重叠的具体交付物。**没有必要信息不能自行编造**：标记 `需确认` 并说明缺口。
5. 创建每条日任务：`分类=每日计划`，`所属进度=[父任务 ID]`，`进度追踪=false`，`AI 拆分状态=无需拆分`，继承可用的 `进度类别/所属项目/优先级`，填写合法计划日期与明确的验收标准，状态默认 `待开始`。父任务真实 `进度追踪`、`本周重点` 不随意重置。
6. 重新读取父任务 `每日步骤` 和子任务 `所属进度`，核验数量、相互关联、名称、日期。**验证全部通过后**才设父任务 `AI 拆分状态=已拆分`。
7. 每次同时按实际日期执行原有周重点与红色逾期待办维护；不得把已完成的历史任务改回待办。
8. 记录本次：候选数、创建父/子项数量、标记已拆分数量、需确认数量、失败原因和重查结果。

## 失败 / 重试 / 幂等保护

- 创建部分子项后若写入失败，不直接重跑创建全部；重新列举现存子项，逐条查重后补缺。不要只靠“已拆分”的状态做唯一去重条件。
- 父任务 `已拆分` 是**输出状态**，不是完成状态。不要因为它“已拆分”就把父任务 `状态` 改成“已完成”。
- `需确认` 在用户填好信息后可手动改回 `待拆分` 以重试；跳过不应自动抹掉已验证的子项。
- 如果任务超出最初范围，不能默默覆盖旧子任务；先说明将影响总分母，再依据用户指示新增。
- 单次写入返回成功并不等于双向 Relation 成功；必须重新读取再确认。
- 不要为了测试而擅自把真实日任务标记为已完成。

## 验证分级

| 等级 | 核验项 | 来源实例已验证？ |
|---|---|---|
| L1 | 待拆分真实父任务可被识别 | 是，立即运行测试 |
| L2 | 子项在同一数据库创建 | 是，2 条 |
| L3 | 父子双向 Relation 正确 | 是，回读确认 |
| L4 | 父任务拆分状态正确更新 | 是，回读确认 |
| L5 | 模板与正式周/月进度隔离 | 是，受控测试过滤/追踪禁用 |
| L6 | 子项完成后的 0/50/100% 实时进度变更 | **尚未端到端验证** |
| L7 | 连续两次相同触发不创建重复行 | **尚未端到端验证** |
| L8 | 无人值守在早间排程执行完整拆分 | **尚未端到端验证** |

## 常见混淆

- 定时“检查”≠ 任务新建的即时触发（非 webhook）。
- “模板样板”页面 ≠ Notion `新建 ▼` 的原生数据库模板。
- AI 按计划“提出步骤并写入”≠ AI 自动判断某任务已完成；完成状态仍由用户操作记录。
- 当前月视图如果只按 `进度追踪=true` 筛选，就不是严格的本月范围。
