# 从 v1 迁移到 v2（不破坏原数据）

## v1 vs v2

| 主题 | v1 | v2 |
|---|---|---|
| 数据模型 | 一个库 + 每日/每周/本月分类 | 保留，新增父子 Relation、Rollup、Formula |
| 完成规则 | 状态/Checkbox 核对 | 状态权威 + 父任务完成率自动计算 |
| 进度展示 | 统计任务完成数量 | 十格文字进度条、周/月及项目图表 |
| 逾期处理 | 提醒/顺延 | 红色 Status、公式提示、跨周/月遗留并持续跟踪 |
| 排序 | 日期/分类 | 添加数值序号，同类任务集中显示 |
| 新任务入口 | 直接在表里新增 | 简单/大型任务样板，独立样板视图 |
| 自动执行 | 可选外部服务 | 可选日常整理；AI 自动拆分**未部署** |

## 安全迁移步骤

1. **备份**当前数据库或导出一份快照。不要覆盖原始用户数据。
2. 读取 Notion 实际 schema（可能与 Skill 文档版本不同），保存字段/视图映射。
3. 添加缺失的 `任务类型`、`进度类别`、`进度追踪`、`本周重点`、`展示序号` 等字段，不覆盖已有同名列。
4. 添加双向自关联：子任务 `所属进度` ↔ 父任务 `每日步骤`。
5. 添加 `步骤完成` Formula、`步骤完成率` Rollup、`进度百分比` Formula、`进度条` Formula。
6. 在**原始真实父任务**上打开 `进度追踪`；为真实每日步骤设置 `所属进度`；不要将整个历史库所有行一次性设成追踪。
7. 配置每日、本周、本月、逾期、未完成和样板视图；所有筛选都要读取视图再次验证确已保存。
8. 再添加 `自动逾期` 和 `逾期提示`。Status 的红色选项在当前计划表中叫 `逾期待办`。
9. 把已过期未完成的父任务加入本周重点；如有真实剩余工作却没有步骤，可新增可验收每日步骤。保留原截止日期。
10. 如需自动转周，另行通过用户授权的调度器配置按日整理；逐项核对结果。
11. 样板入口可以先通过两个复制用的样板记录实现，**不要误称已创建原生 `新建 ▼` 模板**。
12. 按 `tests/` 运行离线规则单元测试；最后在 Notion 真实视图中人工检查一条不影响用户数据的已有记录，不要伪造完成测试。

## 从 v1 升级后需要人工检查

- 未关联的每日任务会被当前“每日执行”筛选隐藏。需要全部日任务可见时改用宽松视图。
- 给已有父任务添加新的每日步骤会改变进度条分母。
- 对分类为 `文书` 或 `CS50P` 但没有子任务的简单任务，可能会走旧 Checkbox fallback，而不是 Status 的 0/100 规则。
- `本月进度` 如果只筛 `进度追踪=true`，并不是严格按月过滤。
- 父任务 `进度百分比=100%` 不会保证 `状态` 自动变为已完成。
- 过去到期的 P3 可选任务也会提示逾期，不代表它比 P0 更紧急。
- 当前版本**不会在用户新增大型任务后立即调用 AI 拆分**，应由用户主动请求或以后单独授权自动化。
