# Automation, rollover, idempotency & limitations

## 能力边界表

| 功能 | 已配置好 Relation/Formula 即实时生效 | 需要额外调度 | v2 Skill 自动启用？ |
|---|---:|---:|---:|
| 子任务完成后更新父任务数字进度 | ✅ | 否 | 否；需先建立 Notion 公式/关系 |
| 动态计算逾期提示文字 | ✅ | 否 | 否；需先建立 Formula |
| 将 Status 真正改为红色“逾期待办” | 否 | ✅（或人工） | 否 |
| 每周一切换“本周重点”勾选 | 否 | ✅（或人工） | 否 |
| 将上月未完成父任务保留在本月 | 依筛选设计 | 可选/建议 | 否 |
| 新增大型任务后 AI 自动拆分 | 否 | ✅且需 AI/Notion 写入 | **没有配置；暂不启用** |
| 复制样板创建任务 | ✅（手动 Duplicate） | 否 | 否 |

## 计划任务的输入

1. 通过用户授权的 Notion 连接获得目标数据库和 data source（不要硬编码公开代码）。
2. 用用户真实时区确定今天、周一、周日。
3. 读取相关父任务（`进度追踪=true`）和关联的每日子任务；优先使用真实状态和截止日期。
4. 只有明确授权后才执行写入；未授权时只建议更改。

## 每日整理：建议伪代码

```python
for parent in tracked_parents:
    # date_range 用真正的开始和截止日；无日期则待用户决定
    parent_in_week = overlaps(parent.date_range, current_monday, current_sunday)
    unfinished = not completed_by_authoritative_status_or_children(parent)
    carryover = parent.deadline < today and unfinished
    parent.weekly_focus = parent_in_week or carryover

for task in relevant_parents_and_daily_children:
    if task.status == '已完成':
        continue  # 不得覆盖真实完成
    if has_deadline(task) and task.deadline < today:
        task.status = '逾期待办'

# 先计算变化摘要，再精确写入，再重新读取验证
```

注意区别：

- 如果父任务的子任务已全部完成（100%），但父任务仍是“进行中”，推荐标记为**待复核 Status**，不要重复纳入“仍未完成的逾期父任务”。
- 如无子任务，`状态` 为事实来源。
- 子任务若为长期运行且没有真正截止日，避免把“开始日期”当到期日。
- 此流程不能在没有调度的普通 Skill 文本中自动运行。

## 幂等性、去重和避免无限创建

- 新增每日子任务前，对同父任务下已有子任务按**标准化名称 + 验收输出 + 日期**匹配；找到了就复用或修改现有行。
- 不要依靠“上次运行成功”推断行已创建；每次运行都重新读取。
- 旧月份所有已完成的日任务应保留，不为“填满月度计划”重新造历史待办。
- 父任务一旦已经有子任务，不能每次轮询都追加相同步骤。若真的新增范围，应明确让分母变化、并通知用户。
- 样板页 `进度追踪=false` 且缺少真实执行日期：不应自动加入周/月进度或被自动标红。
- 任务完成后，只更新真实状态、必要时移出未完成清单；不必删除历史。
- 定时任务修改 `本周重点` 时，需保留周视图排序字段和其他用户自定义属性。

## 跨月逻辑的重要区别

目标逻辑：“本月所有相关追踪父任务”**或**“上月及更早仍未完成的追踪父任务”。

生产案例的月视图目前仅 `进度追踪=true`，因此它**包含所有月份中被追踪的父任务**。这种做法可以快速保留逾期遗留，却会把未来月份已提前设置进度追踪的任务也显示出来。若需要准确月筛选：

1. 新增 `本月展示` Checkbox（推荐先由定时程序计算和更新）。
2. 应用月份条件：任务时间区间与当月有交集 **OR** 截止日早于月初且未完成。
3. 月视图筛选 `进度追踪=true AND 本月展示=true`。
4. 对已完成历史记录保留在原始表，不放入新月目标统计（除非用户明确要求复盘）。
5. 对下月未来任务不提前纳入本月完成率。

**此流程是建议的后续增强，不应写作“已经部署”。**

## 已知连接器限制与恢复

- 有的 Notion 连接器可能接受创建 Formula 列，却不接受公式布尔值作为视图的筛选条件。发生时保留 `本周重点` Checkbox 视图筛选，并使用授权的定时维护。
- Notion CSV 导入不会创建 Rollup、Formula、Relation、View、Native Template、调度。
- Notion 连接器可能无法创建 `新建 ▼` 中的原生数据库模板；可先用 **模板样板行 + Duplicate**。如用户必须拥有原生模板，提供 Notion UI 的手动配置步骤。
- 任务检查服务通常按计划时间附近执行，**不保证精确到分钟**；若失败要告知未更新，不可以宣称“自动完成”。
- 公式 `today()` 的日期和调度器的时区可能不同；实际到期判定必须以用户设定的本地日历日期检查。
- 需要刷新视图但 Notion API 更新失败：先读取当前视图，撤销有害的残缺筛选，再进行最小幅度修正，不做大规模覆盖。

## 安全与审计

日志至少记录运行日期（含时区）、目标 data source、读取父任务数、追加日任务数、更新状态数、跳过的已完成行数、异常及复查结果。不要把真实任务、登录信息、Notion 私有 URL 上传公开 repo。用 `.local.*` 或环境变量保存个人连接配置，并纳入 `.gitignore`。
